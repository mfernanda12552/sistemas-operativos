Introducción

Un Sistema Operativo (S.O.) es el software fundamental que actúa como intermediario entre el usuario, las aplicaciones y el hardware de una computadora. Sin él, los componentes físicos como el procesador, la memoria RAM o las unidades de almacenamiento serían sumamente complejos de operar de manera directa y segura.

El presente sitio web recopila y estructura los pilares teóricos y prácticos estudiados a lo largo del curso: desde los primeros dispositivos mecánicos de cálculo y las generaciones de computadoras, hasta la gestión interna de procesos, hilos y prevención de interbloqueos mediante el Algoritmo del Banquero, culminando con un análisis reflexivo y una comparativa técnica de los sistemas operativos orientados a servidores empresariales.

01

Orígenes y Evolución Temprana de la Tecnología

Antes de la existencia de los sistemas operativos digitales, la computación atravesó siglos de innovación mecánica y electromecánica para automatizar el cálculo matemático y el procesamiento de información.

Antigüedad – Siglo XVII | Herramientas Mecánicas

Desde el ábaco hasta la Pascalina de Blaise Pascal (1642) y la calculadora escalonada de Leibniz, las primeras máquinas realizaban operaciones aritméticas básicas mediante engranajes.

1801 – 1837 | Tarjetas Perforadas y Máquina Analítica

Joseph Marie Jacquard automatizó telares usando tarjetas perforadas. Posteriormente, Charles Babbage diseñó la Máquina Analítica (con unidad aritmética, memoria y entrada/salida) y Ada Lovelace escribió el primer algoritmo pensado para ser procesado por una máquina.

1890 – 1940 | Tabulación Electromecánica y Relés

Herman Hollerith creó máquinas tabuladoras para el censo de EE. UU. (origen de IBM). Konrad Zuse (Z3) y Howard Aiken (Harvard Mark I) introdujeron calculadoras electromecánicas programables.

1945 | Arquitectura de Von Neumann y Tubos de Vacío

Con máquinas como ENIAC y EDVAC se estableció el concepto de programa almacenado en memoria, sentando las bases estructurales de todas las computadoras modernas.

02

Breve Historia de los Sistemas Operativos

Década de 1950: Sistemas por Lotes (Batch)

Las primeras computadoras carecían de S.O.; se operaban desde consolas con interruptores. General Motors desarrolló en 1956 el GM-NAA I/O para la IBM 704, considerado el primer sistema operativo funcional, capaz de ejecutar trabajos en lote mediante cintas magnéticas.

Década de 1960: Multiprogramación y Tiempo Compartido

Nace OS/360 de IBM para unificar familias de hardware. En el MIT surge MULTICS, inspirando a Ken Thompson y Dennis Ritchie (Bell Labs) a crear UNIX (1969), reescrito en lenguaje C, portable y multiusuario.

Década de 1980: Computadoras Personales y GUI

La microcomputadora populariza CP/M y MS-DOS (Microsoft). Apple lanza Macintosh (1984) con interfaz gráfica (GUI) y ratón, seguido por las primeras versiones de Microsoft Windows.

1991 – Actualidad: Código Abierto, Móviles y Nube

Linus Torvalds libera el kernel Linux (1991) bajo licencia libre. En el siglo XXI dominan los S.O. móviles (Android, iOS), la virtualización, contenedores y sistemas distribuidos en la nube.

Evolución de los Sistemas Operativos

La evolución técnica de los sistemas operativos se divide tradicionalmente en generaciones vinculadas al avance del hardware:

Generación Período Tecnología Hardware Características del Sistema Operativo
1ª Generación 1945 – 1955 Tubos de vacío y tableros enchufables Sin S.O. Programación directa en lenguaje máquina y tarjetas perforadas.
2ª Generación 1955 – 1965 Transistores y mainframes Sistemas de procesamiento por lotes (Batch) y monitores residentes (FMS, IBSYS).
3ª Generación 1965 – 1980 Circuitos integrados (IC) Multiprogramación, spooling, tiempo compartido (Timesharing) y UNIX.
4ª Generación 1980 – 2000 Microprocesadores (LSI / VLSI) Sistemas operativos personales, interfaces gráficas (GUI), redes y sistemas distribuidos.
5ª Generación 2000 – Presente Multinúcleo, SoC móvil y Cloud Computación móvil, virtualización (hipervisores), contenedores e integración con IA.

Hardware y Software de la Computadora

🔧 Hardware (Nivel Físico)

Conjunto de componentes tangibles, electrónicos y electromecánicos que ejecutan las instrucciones:

  • CPU (Procesador): Unidad de Control, ALU y registros que ejecutan ciclos de instrucción.
  • Memoria Principal (RAM): Almacenamiento volátil de alta velocidad para programas en ejecución.
  • Almacenamiento Secundario: Unidades SSD, NVMe y HDD para persistencia de datos.
  • Dispositivos de E/S y Buses: Tarjetas de red, GPU, periféricos y canales de comunicación PCIe/USB.

💿 Software (Nivel Lógico)

Conjunto de programas, instrucciones y reglas lógicas que indican al hardware qué tareas realizar:

  • Firmware (BIOS / UEFI): Software grabado en memoria no volátil que inicializa el hardware al encender el equipo.
  • Software de Sistema: Sistemas operativos, controladores (drivers) y utilidades de diagnóstico.
  • Software de Desarrollo: Compiladores, intérpretes, depuradores y entornos IDE.
  • Software de Aplicación: Navegadores, suites ofimáticas, ERP, videojuegos y apps móviles.
05

Ecosistema del Sistema Operativo

El sistema operativo no trabaja aislado; forma parte de una arquitectura en capas que conecta al usuario final con la electrónica del equipo:

1. Usuarios y Aplicaciones

Interactúan mediante interfaces gráficas (GUI) o líneas de comando (CLI/Shell).

2. APIs y Llamadas al Sistema

Interfaz programática (POSIX, Win32) mediante la cual las apps solicitan servicios al núcleo.

3. Kernel y Controladores

Núcleo privilegiado (Modo Kernel) y drivers que traducen órdenes hacia el hardware físico.

06

Componentes del Sistema Operativo

⚙️ Gestión de Procesos

Crea, planifica, suspende y finaliza procesos, gestionando la sincronización y comunicación entre ellos (IPC).

🧠 Gestión de Memoria Principal

Asigna y libera bloques de RAM, implementa paginación, segmentación y memoria virtual para aislar procesos.

📁 Gestión de Archivos

Organiza datos en directorios y sistemas de archivos (NTFS, ext4, APFS, ZFS) controlando permisos de acceso.

🔌 Gestión de Entrada/Salida (E/S)

Abstrae las diferencias del hardware mediante buffering, caching, spooling y controladores de dispositivos.

🛡️ Protección y Seguridad

Controla la autenticación de usuarios, privilegios (usuario vs. root/admin) y defensa frente a accesos no autorizados.

🌐 Redes e Intérprete de Comandos

Implementa pilas de protocolos (TCP/IP) y provee el Shell (Bash, PowerShell) para ejecutar instrucciones del usuario.

Algoritmo del Banquero

Diseñado por Edsger Dijkstra (1965), el Algoritmo del Banquero es un método clásico de evitación de interbloqueos (Deadlocks). Su nombre proviene de la analogía con un banquero que nunca asigna efectivo de tal manera que no pueda satisfacer las necesidades máximas de al menos uno de sus clientes.

Antes de conceder un recurso solicitado por un proceso, el sistema simula la asignación y verifica si el estado resultante es seguro (es decir, si existe al menos una secuencia segura en la que todos los procesos puedan terminar su ejecución).

08

Hilos (Threads)

Un hilo (thread) o proceso ligero es la unidad básica de utilización de la CPU. Un mismo proceso puede contener múltiples hilos que se ejecutan de manera concurrente o paralela.

¿Qué comparten los hilos de un proceso?

  • Espacio de direcciones de memoria (código y variables globales).
  • Archivos abiertos y conexiones de red.
  • Recursos asignados por el sistema operativo.

¿Qué posee cada hilo de forma independiente?

  • Identificador único de hilo (Thread ID).
  • Contador de programa (Program Counter).
  • Conjunto de registros de CPU y pila propia (Stack).

Ventajas del Multithreading: Mayor capacidad de respuesta en interfaces, compartición eficiente de recursos sin sobrecarga de memoria, economía en creación/cambio de contexto y aprovechamiento real de arquitecturas multinúcleo (SMP).

09

Procesos

Un proceso es un programa en ejecución. Mientras que un programa es una entidad pasiva almacenada en disco (un archivo ejecutable), un proceso es una entidad activa con un estado actual, contador de programa y recursos asignados, administrado por el S.O. mediante su PCB (Process Control Block).

Comparación de los Sistemas Operativos para Servidores

A diferencia de los sistemas de escritorio, los S.O. para servidores priorizan la estabilidad ininterrumpida (uptime), el rendimiento bajo alta concurrencia de red, la virtualización y la seguridad empresarial.

Criterio Linux Server (RHEL / Ubuntu Server / Debian) Windows Server (2022 / 2025) Unix / BSD (FreeBSD / AIX)
Licenciamiento Código abierto (GPL); gratuito o con suscripción de soporte empresarial (Red Hat, Canonical). Propietario y comercial (licenciamiento por núcleos físicos y CALs). Código abierto permisivo (licencia BSD) o propietario (IBM AIX, Oracle Solaris).
Interfaz Principal Línea de comandos (CLI / SSH) sin entorno gráfico por defecto para ahorrar recursos. GUI completa (Desktop Experience) o Server Core administrado vía PowerShell / Windows Admin Center. Línea de comandos (CLI / SSH) altamente minimalista y modular.
Casos de Uso Ideales Servidores web (Nginx/Apache), nube pública, contenedores (Docker/Kubernetes) y bases de datos. Active Directory, entornos corporativos Microsoft, Exchange, SQL Server y aplicaciones .NET. Infraestructura de red de alto rendimiento, firewalls, almacenamiento ZFS (TrueNAS) y mainframes bancarios.
Estabilidad y Reinicios Muy alta; soporta actualizaciones en caliente del kernel (Livepatch) sin reiniciar. Alta, aunque las actualizaciones críticas suelen requerir reinicios programados. Extrema; reconocido por años de actividad continua sin interrupciones.
Seguridad Permisos granulares, SELinux, AppArmor y rápida auditoría comunitaria. Integración nativa con Active Directory, BitLocker, Windows Defender ATP y políticas de grupo (GPO). Aislamiento mediante Jails (FreeBSD), arquitectura limpia y baja superficie de ataque.
